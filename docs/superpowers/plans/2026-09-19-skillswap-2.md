# SkillSwap 2.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a polished, fully interactive local-first skill exchange demo at the existing GitHub Pages URL.

**Architecture:** A static application shell renders hash-routed views from a versioned local state store. Pure matching functions are tested independently; browser-only modules handle persistence, uploads, media capture, and DOM interactions.

**Tech Stack:** HTML5, CSS, vanilla ES modules, Node built-in test runner, LocalStorage, IndexedDB, MediaDevices APIs.

**Spec:** `docs/superpowers/specs/2026-09-19-skillswap-2-design.md`

## Global Constraints

- Preserve the current public GitHub Pages domain and use only relative asset URLs.
- No backend, account verification, build system, or runtime dependency.
- Body text 15–16px; navigation and card details at least 14px.
- All core state survives refresh and can be reset.

## Review Focus

- Empty or incomplete onboarding must not produce invalid matches.
- Skill arrays of different lengths must score deterministically.
- No shared availability must be explained rather than hidden.
- Denied media permissions must keep the classroom usable.
- Uploaded files over 20MB or beyond the three-file limit must be rejected clearly.
